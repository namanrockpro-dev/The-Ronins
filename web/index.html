Mission Briefing

▸ Objective

India's Chandrayaan-2 orbiter carries three imaging instruments — OHRC (25 cm/px), TMC-2 (5 m/px), and IIRS (256-band hyperspectral). These generate massive image strips of the lunar surface under varying illumination conditions. Accurately registering a reference region within a full target scene is essential for change detection, landing site selection, and geological mapping. LunarMatch AI solves this as an adaptive, self-correcting registration pipeline that works entirely offline.

▸ The Problem

Lunar surface images are uniquely challenging. There is no atmosphere for scattering — shadows are razor-sharp. The same crater can look completely different under two sun angles. Resolution varies by 200× between sensors. Traditional feature matchers fail when illumination changes dramatically, and manual registration of 900 MB strips is impractical. The system must automatically detect, match, verify, and report — or intelligently fall back to an alternative strategy.

Core Technology Stack
LoFTR Neural Matcher Transformer-based dense correspondence without keypoint detection
▸

LoFTR (Detector-Free Local Feature Matching with Transformers) replaces the traditional detect-then-describe paradigm. Instead of finding keypoints first, it uses a coarse-to-fine transformer architecture to establish dense pixel correspondences directly between two images.

The model processes both images through a CNN backbone, then uses self-attention and cross-attention transformer layers to reason about relationships between all pixel positions simultaneously. This allows it to match textureless or repetitive regions where classical detectors like SIFT or ORB fail completely.

In LunarMatch, LoFTR is the high-confidence matcher — selected automatically when the difficulty estimator detects challenging conditions (high blur, low texture, large sun angle difference). It runs on GPU via PyTorch + Kornia with automatic CPU fallback.

Backend: PyTorch + Kornia Weights: outdoor pretrained Confidence gate: > 0.15 File: src/features.py
SIFT Feature Detector Scale-invariant keypoint detection with 128-D descriptors
▸

Scale-Invariant Feature Transform detects blob-like keypoints at multiple scales using Difference-of-Gaussian (DoG) pyramids. Each keypoint gets a 128-dimensional descriptor based on local gradient orientations, making it robust to scale changes and moderate viewpoint shifts.

In LunarMatch, SIFT serves as the workhorse matcher for medium-difficulty pairs. It is selected when difficulty is between 0.30 and 0.55. We use up to 8000 keypoints with a contrast threshold of 0.01, matched via FLANN (5 KD-trees) with Lowe's ratio test at 0.75.

SIFT also provides the baseline comparison metric — every result shows "Our Pipeline vs SIFT Baseline" so evaluators can see the adaptive improvement.

nfeatures: 8000 Ratio test: 0.75 FLANN: 5 trees / 50 checks File: src/features.py
Lunar Preprocessing Engine CLAHE + Hapke correction + shadow-invariant imaging
▸

The Moon has no atmosphere. Shadows are absolute black with razor-sharp edges. Two images of the same surface under different sun angles can be completely unrecognizable to each other. Our preprocessing chain is specifically designed for this:

  • Bilateral Filtering — Smooths noise while preserving crater edges
  • Percentile Normalization — Clips extreme values (2nd–98th percentile) to use the full dynamic range
  • CLAHE — Contrast Limited Adaptive Histogram Equalization with clip=1.8 on 8×8 tiles brings out surface detail in shadowed regions
  • Hapke Photometric Correction — Uses incidence angle metadata to mathematically reduce illumination-dependent brightness variation, based on the Hapke bidirectional reflectance model used in planetary science
  • Shadow-Invariant Channel — Computes Sobel gradient magnitudes to extract structural features that remain visible regardless of lighting direction
  • Adaptive Blending — Final image is 70% photometric + 30% structural, creating a representation that is robust under any illumination
CLAHE: clip=1.8, 8×8 Blend: 0.7 Hapke + 0.3 shadow Pyramid: 4 levels File: src/pre1.py
Geometric Verification MAGSAC++ with GC-RANSAC refinement and sub-pixel accuracy
▸

Raw feature matches always contain outliers — incorrect correspondences that would ruin the geometric estimate. Our verification pipeline removes them through progressively tighter filtering:

  • MAGSAC++ — Marginalizing Sample Consensus estimates homography/affine transforms without needing a manual inlier threshold. It automatically adapts to the noise level in each image pair
  • GC-RANSAC Refinement — Graph-Cut RANSAC provides a second pass that exploits spatial coherency among inliers for tighter estimation
  • Sub-Pixel Refinement — cv2.cornerSubPix() and Lucas-Kanade optical flow push keypoint locations from integer pixels to fractional precision (e.g., x=100 → x=100.27)
  • ANMS — Adaptive Non-Maximal Suppression distributes matches across an 8×8 grid to prevent clustering in one region
Method: Homography / Affine RANSAC: 10000 iterations Sub-pixel: cornerSubPix + LK File: src/geom.py
Self-Correcting Pipeline Automatic fallback chain — adjusts strategy when quality gate fails
▸

This is what makes LunarMatch adaptive. Instead of a fixed algorithm, the system evaluates its own results and retries with a different strategy if quality is insufficient:

  • Quality Gate — Pass requires inlier ratio > 60% AND RMSE < 2.0 pixels. Marginal: inlier > 35% AND RMSE < 4.0. Otherwise: fallback
  • Round 1 — Standard preprocessing with difficulty-selected matcher (ORB/SIFT/LoFTR)
  • Round 2 — Stronger Hapke correction + enhanced processing chain + model swap
  • Round 3 — Full shadow-invariant channel with cross-modal matching
  • Difficulty Estimator — Analyzes blur, texture entropy, sun angle difference, resolution gap to select the optimal matcher automatically

The system tries up to 3 rounds, switching between ORB → SIFT → LoFTR (or any adaptive ordering) until the quality gate passes or all strategies are exhausted.

Gate: 60% inliers + 2px RMSE Max rounds: 3 Auto model selection File: src/pipeline.py
Chandrayaan-2 PDS4 Reader Native support for PRADAN ZIP archives up to 900MB+
▸

Chandrayaan-2 science data is distributed by ISRO's PRADAN portal in PDS4 format — ZIP archives containing XML labels and binary image payloads. These files can be enormous (TMC-2 strips reach 900 MB+).

Our I/O module handles this natively without loading the entire file into RAM:

  • ZIP Extraction — Extracts only the image payload, not the entire archive
  • NumPy Memory-Mapping — Uses np.memmap to access pixel data on disk without full materialization
  • Metadata Extraction — Parses XML labels for sensor type, sun azimuth/elevation, incidence angle, corner coordinates, observation time
  • Multi-Sensor — Automatically identifies OHRC (25 cm), TMC-2 (5 m), IIRS (256-band) and applies sensor-appropriate processing
  • IIRS Hyperspectral — Selects representative bands from the 256-channel cube to create a matchable composite
Formats: PDS4 ZIP, PNG, TIFF Max tested: 900MB strip Memory: disk-mapped File: src/io_pds.py
Future Innovations
01

Fine-Tuned Lunar LoFTR

Train a LoFTR variant specifically on lunar surface imagery — craters, rilles, mares, highlands under extreme lighting. The current outdoor-pretrained weights work well, but a model fine-tuned on thousands of Chandrayaan-2 image pairs would dramatically improve matching confidence on textureless regolith and shadowed polar regions.

Planned — Dataset curation in progress
02

Safe Rover Landing Zone Prediction

Use the registration pipeline's geometric understanding to identify flat, shadow-free, boulder-free landing zones. By combining multi-temporal registered images with slope analysis from stereo TMC-2 pairs, the system could automatically score candidate landing sites for future missions like Chandrayaan-4.

Research — Feasibility study phase
03

Temporal Change Detection

With sub-pixel registration accuracy, compare images of the same region taken months apart to detect surface changes — new impact craters, regolith movement, volatile deposits near permanently shadowed regions. This requires the registration quality that LunarMatch provides as a prerequisite.

Planned — Dependent on registration accuracy
04

Cross-Sensor Fusion

Register OHRC (25 cm visible) onto IIRS (256-band hyperspectral) to create high-resolution mineralogy maps. This combines the spatial detail of OHRC with the spectral richness of IIRS, enabling identification of specific minerals at unprecedented resolution.

Research — Cross-modal matching prototype
